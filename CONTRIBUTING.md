# Contributing to systemDesingo

Thanks for wanting to help make this a better way to prep for distributed-systems
interviews! Contributions are welcome — with a light review so the bar stays high.

## The easiest way to help: open an Issue

You don't need to touch code. The most valuable contributions are:

- **✍️ Suggest a question / drill** — a concept worth adding, with the answer and a
  one-line "why". Use the *Suggest a question or drill* issue template.
- **🐛 Report a wrong answer** — spotted an incorrect answer or a misleading
  explanation? Use the *Report a wrong answer* issue template. Please quote the
  exact question so it's findable.

## Pull requests

PRs are welcome too, but **everything is reviewed before merging** — nothing is
auto-merged. To keep the material consistent:

- **Keep it interview-relevant.** Favor the core concepts an interviewer actually
  probes over niche jargon or excessive depth.
- **Be accurate.** Answers and explanations should be correct and defensible;
  include a short rationale, not just the answer.
- **Be concise.** Match the existing terse, high-signal style of the drills.
- The app is a single self-contained file — `distributed_systems_prep_v2.html`.
  Content lives in the data arrays inside it; match the surrounding shape.
- Test locally by opening the file in a browser before submitting.
